# Part2：0.1.41 批量文件读取与首次预填充 — 2026-10-09

日常 coding 已更新到上游 **0.1.41 / fb58e0d** 加既有本地优化。两个独立进程中，10 个全新输入的预填充合计从 **150.08 /155.06 秒**降至 **89.61 /89.51 秒**，合计耗时减少 **41.30%**。2K–5K 输入的四次观测中位数下降约 **47–56%**。收益来自接入上游的批量文件读取；本轮没有宣称新的 decode 加速。

全部模型测试保持 NVIDIA **537.13**、2080 Ti **310 W**、P100 **250 W**。硬件仍为 i7-13850HX、32 GB RAM、2080 Ti 22 GiB、P100 16 GiB；主卡 PCIe 3 x16、P100 PCIe 3 x4，无 P2P。没有安装或更新驱动。模型、专家画像、spec8 / min-p0.9、8192 上下文、INT8 KV 和原线程设置保持此前测试条件。

## 采用的改动

此前日常的完整 resident 配置没有设置 `--resident-budget-gib`，因此不会进入上游按内存容量选择的 unbuffered 文件读取路径。预填充仍会重新读取 P100 缓存内、以及主卡暂时借出槽位中的专家；这些专家没有重复放入 CPU 常驻副本。

本轮给 coding 配置增加 **`--resident-budget-gib 12`**。这是上限，实际 CPU 专家副本仍是完整的 **10.84 GiB**，经 VirtualLock 驻留。启动日志确认 CPU 副本建好后有约 12.7 GiB 可用 RAM，而文件层还涉及约 29.1 GiB 专家。上游已有的容量判断由此选择 unbuffered I/O，并关闭 `experts.bin` 的映射，使新的批量读取能够使用。没有硬编码文件 I/O 开关、线程数或批次大小。

批量读取、读取合并和映射关闭均来自上游 0.1.41。本地集成保留已验证的 HC/embedding 缓冲复用、helper 输出优化和共享前缀修复；将文件页释放补丁适配到新的 Stager 批次，在主机复制结束后、发布 ready 标记前释放来源文件页。稳定指针继续 `memcpy`，临时来源继续 `copy_blobs`。

`STRATA_STAGE_PIN=0` 显式保留关闭状态：上游 fb58e0d 已因异步阶段缓冲重用导致的错误撤回默认开启。本轮没有重新开启它。12 GiB 预算是本机采用值，不作为上游通用默认。

Windows 约每秒采样，从第一个正式请求到最后一个请求结束，不含启动。C: 对应 PhysicalDrive2；两轮基线系统级物理读取约 **95.73 /94.59 GiB**，采用配置约 **103.67 /103.68 GiB**。改进是更快地读取，并非减少读取字节。计数包括该盘其他活动及采样边界误差。`files N blobs` 日志计数在标量与批量路径中覆盖不同调用，不能拿它推导读取量下降。

## 没有采用的参数

显式 `STRATA_PREFILL_CPU_SHARE=auto`、`STRATA_PREFILL_CPU_SHARE_MAX=3072` 的合计时间约比 direct-a 少 2.9%，但首次 2067-token 源码读取由 10.319 增至 12.539 秒；逐项结果混合，未建立稳定的额外收益，因此没有增加这两个配置值。

helper 模式下，上游默认 CPU share 会被 arm，因为代码中的 `multi_gpu` 指层切分；但 `short-read1024` 会让小输入先走 decode windows。启动显示 ON 不代表每条短请求都使用了 CPU 分担。把阈值降到 128 后，422-token 请求从 3.761 /3.725 秒变成 7.202 /6.972 秒，完整序列也更慢，故保留1024。

新的无 P2P peer prefill 路径仍与当前 helper 专家缓存配置互斥，本轮没有切换或测量。没有打开 route-resident、阶段缓冲 pinning 或其他改变路由/数值的研究开关。
