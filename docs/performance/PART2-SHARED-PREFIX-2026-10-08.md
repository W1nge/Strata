## 修复与配置

`strata_prefix` 和会话停车均为上游已有功能。本轮新增的是固定前缀的生命周期修复：原实现只更新当前检查点链的 `pinned` 标记，已经停放的旧文档仍不可淘汰。客户端固定文档 A、修改为 B、再回到 A 后，两份旧快照可以占满两个槽位；即使字节预算还有空间，后续停车仍被拒绝。

现在，合法的新显式前缀请求在选择、取出快照之前，按 token 前缀、边界、图像身份和 steering 模式取消旧前缀的固定标记。处理当前检查点、批处理槽位和停放的会话；保留匹配前缀的固定标记。旧快照的数据和匹配能力保留，内存或槽位不足时按原规则淘汰。没有新增 CLI 开关、机型判断或数值计算改动。生产代码 **27 行**，另加 **44 行**回归测试，合计 **3 文件、+71 行**。

本机 coding 配置调整为：

```text
--prompt-cache 3
--conversation-cache-mib 1536
--conversation-cache-slots 2
--conversation-cache-min-free-mib 6144
```

停车预算为 1.5 GiB，RAM 准入保留 6 GiB 余量；不足时沿用正常提示词处理。`--prompt-cache-every 65536` 保留。以上是本机采用值，不作为上游通用默认值。

会话交替的历史复用自动按 token / 图像匹配。独立问题共享文档的收益需要客户端标记 `strata_prefix`：本轮把源文件与问题放在同一条 user 消息中，用 `{"message": 1, "chars": 文档前缀字符数}` 标记边界。普通的连续会话原本就有 live/checkpoint 复用；本轮没有宣称所有客户端都会自动固定任意文档。仓库已有 `tools/research_run.py --prefix on` 可用于文档问答。
