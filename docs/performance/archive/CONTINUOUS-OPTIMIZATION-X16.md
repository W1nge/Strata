# PCIe x16 优化结果

已完成本轮参数与热点路径筛选，采用可重复的新题收益组合，并应用到日常配置。普通服务正在本机 8080 端口运行，关闭性能诊断计时。保留原 Q3 权重、量化、专家 top-k 和 32768 上下文。

## 确认的收益

6 道新题，温度 0、关闭思考、max_tokens=256，1 轮预热及 4 轮正式对照，共 90 个请求。每道题轮换 3 组设置顺序；预热不计入速度。

| 设置 | 解码 token/s |
|---|---:|
| 本轮基准：CPU 分片 3、MTP 阈值 0.4、完整图 | 54.682 |
| CPU 分片 12、MTP 阈值 0.8、完整图 | 58.196 |
| 最终组合：再省略空 PCIe 图分支 | 59.360 |

最终组合提升 **8.55%**，四轮均更快；按题目聚类重采样的 95% 收益区间为 **6.41% ～ 11.97%**。吞吐按总生成 token 数除以总解码时间计算，不含输入处理，不能当作所有任务的速度保证。

空图优化单独在原 12 题上提升 1.45%，在新 6 题上提升 2.00%；两组分别 36/36 和 24/24 个正式输出逐字相同。完整图对照使用 pcie_frac=1/256：最多 80 个不同专家，整数分配仍为零，只保留图节点。基准和候选实际都没有在解码中搬运 PCIe 专家。

MTP 阈值会改变浮点批次路径，因此累计组合与原基准只有 20/24 个正式输出逐字相同，不能宣称所有设置 bit-exact。两个代码题的 30 份 Python/SQL 输出均通过边界案例检查；这是有限样本验证，不是全面质量评测。

## 已应用的参数

`--native-tasks 12 --spec-min-p 0.8 --spec 4 --pcie-frac 0 --skip-empty-pcie --adapt-every 0 --host-budget-gib 10 --max-context 32768`

预取保持默认 4 线程，CPU 排序及单 token 内核保持默认，AVX-VNNI 实验开关关闭。MTP 窗口为 4，suffix 可以使用内部容量 6。日常配置明确 pcie_frac=0，避免 Windows DMA 能力修复后自动分配的比例在本机造成退化。以上收益相对共同关闭 PCIe 解码分工的本轮基准，不是与旧 x4 报告直接比较。

配置备份：strata-iq3xxs-native.before-x16.json；实际配置副本：strata-iq3xxs-native.x16.json。源码补丁 strata-x16-final.patch 基于 e287ed0，包含本轮前面已提交的内存、VNNI、计时及 Windows DMA 修复和最终未提交改动。

## 收敛依据

| 候选 | 结果与选择 |
|---|---|
| MTP 阈值 0、0.2、0.6、0.7、0.9；窗口 6/8 | 未超过 0.8、窗口 4 的稳定收益 |
| CPU 分片 3/6/12/16、三类单 token 内核、4 种队列顺序 | 保留分片 12 和默认内核/顺序；剩余收益区间跨零或退化 |
| AVX-VNNI | 实际启用后 58.573，对照 58.571，未见收益 |
| 主机缓存 6/8/10 GiB | 小预算未加速，保留 10 GiB |
| 预取 4/12/16、关闭 | 12/16 略慢；关闭虽热态约 +0.6%，首次一轮从约 42 降至约 36，保留 4 |
| 动态缓存每 4 轮/96 次换入 | 40.25 token/s，明显退化 |
| 动态缓存每 16 轮/16 次换入 | 延长 8 轮仍在 52～59 间波动，平均 55.84，保留静态 |
| DMA 6.25%/12.5%/25% | 初筛小收益不稳定；针对新空图基准的 4 轮确认中，6.25%/12.5% 每轮都落后，保留 0 |

主机缓存与预取采用前后静态对照，热态漂移约 0.13%。这些跨进程数据用于筛选；首次一轮没有清空 OS 缓存，不能当作严格的冷盘测量。更早 x4 阶段的速度仅作历史记录。

## 剩余瓶颈

最终候选在 12 题热态轻量计时中，每验证窗口约 32.39 ms，平均提交 1.924 token。主机等待 GPU 推进约 16.25 ms，CPU 专家计算及内存等待约 9.86 ms，草稿约 2.89 ms。CPU 内 gate/up 约 6.41 ms、down 约 3.34 ms。

GPU 等待是主机侧区间，不能当作纯 GPU 内核计时；子项不能重复相加。短输入热态已同时受 GPU 推进和 CPU/内存路径限制。新任务还会受缺页影响，AVX-VNNI 不能解决整个等待链。本轮有证据支持的调度、预取、缓存和图路径候选已经收敛，不代表不存在新的内核或硬件方案。

## 验证与限制

- 普通运行模式：事实题、Fibonacci 边界案例通过。
- 16K/32K 输入的 10%/50%/90% 深度召回 **6/6 通过**；较长组实际输入 31,239～31,241 token，服务上限确认 32768。
- Windows tiered 测试通过；扩展 CTest **28/29 通过**。PLE 对照因缺少它要求的原始 Q2_0 表及 block 样本，在数值比较前失败；没有把这一项算作通过。
- 用户调整 GPU 配置为相同电压下核心降低 50 MHz，其余不变。之后原始 GPU 内核 130000 次 Graph/eager 对照通过，支持此前超频配置稳定性不足；这不能证明永久稳定或显卡物理损坏。
- 一次历史 CPU 0xc0000005 的根因仍未确认；后续 400 次 CPU 对拍和 **1902 个完整模型基准请求**未复现。该失败扫描已排除，不用于性能选择。完整定位记录保留在证据包。
