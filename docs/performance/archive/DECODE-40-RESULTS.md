# Q3 解码优化结果

2026-10-02；原有 IQ3_XXS 权重，Windows / RTX 2080 Ti 22 GB / 32 GB RAM。

**最终原六题基准：49.38 token/s。新增六题基准：46.35 token/s。**
两组各 18 次请求，均保留第一轮。结果是指定任务集的汇总解码速度；首次访问新主题、长上下文和
后台内存压力下仍可能低于 40，不能理解为每次请求的最低速度保证。

## 已部署的改变

1. 按实时显存驻留表决定是否预取冷专家，并对同一窗口的重复专家去重。
2. Windows 上用 `VirtualUnlock` 移出已经复制到显存或 pinned arena 的冗余文件映射页。
   同时覆盖启动加载、动态交换和长提示处理后的显存缓存回填；只在复制完成后操作，范围按页向内取整。
   不改变文件字节，也不释放 pinned arena。`STRATA_NO_VIEW_TRIM=1` 可禁用这项提示。
3. 日常配置保留 `--host-budget-gib 10 --spec 4 --spec-min-p 0.4`，增加 `--adapt-every 0`。
   本机 PCIe 约 3.3 GB/s，持续交换专家会带来传输和等待；固定既有用户画像更快。

原来的 `C:/strata-models/run-iq3xxs-native.bat` 继续可用，正常 JSON 已更新。当前 8080 服务已运行最终版本，
使用 work 中等价配置并开启诊断日志。无需另外启动第二个模型进程。

权重、量化档位、专家 top-k、32K 上下文上限均未改变。Q2 AVX-VNNI 内核仍默认关闭：此前只证明了
局部微基准收益。CPU 没有 AVX-512，但本次主要收益来自内存驻留与交换策略。

## 测量方法与结果

解码速度 = 总生成 token / 总引擎 decode 秒数；不是请求速度的算术平均，不包含 prefill。
原六题每题上限 128 token；新增六题涵盖中文科学、历史、统计、英文数据库、物理及 Python 区间合并，
每题上限 256 token。两者均 temperature 0、reasoning none、固定顺序跑三轮。
最终原六题为 1419 token / 28.7382 s；新增六题为
4456 token / 96.1361 s。

| 配置/任务集 | 汇总 decode tok/s | 三轮各自汇总 tok/s | 含输入处理的 HTTP tok/s |
|---|---:|---|---:|
| 此前 AVX2 / 10 GiB | 24.88 | 18.25 / 25.75 / 36.60 | 19.63 |
| 修正预取 | 28.68 | 19.42 / 35.12 / 40.83 | 22.60 |
| 再释放冗余映射页 | 35.24 | 27.28 / 40.75 / 41.78 | 27.11 |
| 再关闭动态交换（初测） | 49.83 | 37.03 / 60.20 / 60.28 | 38.78 |
| 最终版本：原六题 | 49.38 | 36.11 / 60.44 / 60.52 | 38.44 |
| 最终版本：新增六题 | 46.35 | 40.72 / 51.72 / 48.12 | 41.53 |

不同试验间没有清空 Windows 文件缓存，启动次序、热身和生成文本有差别；表格是观测结果，
不能把各行比例认定为已经隔离其他因素后的独立因果收益。早期文档中的 17.4 tok/s 使用的生成上限也不同。

内存释放单独验证：16 MiB 测试映射的 4096 个工作集驻留页移出后为 0 个，重新读取字节完全一致。
整机 10 GiB pinned 初测中，加载后工作集约 11.5 GiB、可用 RAM 14.4 GiB；旧路径通常只剩几百 MiB。
后续请求会重新使用空闲内存，长提示仍可造成压力，这不是永久固定的空闲容量。

额外边界测试也保留：前一版在长提示召回测试后立即换六个新主题，首轮 27.08、第二轮 48.20，
合计 34.67 tok/s（每题上限 256、两轮）。这说明热身与换主题延迟仍是真实限制。
取消全部 pinned 区、把草稿阈值降到 0，均未获得更好的整体结果，没有选为日常设置。

## 恢复

恢复动态交换只需把正常 JSON 的 `--adapt-every` 改回 `4` 并重启服务。
完整回退使用此前 `strata-before-changes.zip` 中的原始 exe、配置和启动器；停止本服务后再替换文件。
模型文件无需重新下载或转换。
