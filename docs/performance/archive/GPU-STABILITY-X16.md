# PCIe x16 后的稳定性证据

PCIe 接触修复后已验证为 PCIe 3.0 x16，启动 H2D 约 13.3 GB/s。旧报告中的 x4 / 3.3 GB/s 仅作历史记录。

## 参数调整后的结果

用户确认原降压超频配置异常，并在相同电压下将核心频率降低50 MHz，其余设置不变。这不是恢复出厂默认设置。

- 未修改的原始内核：3轮×10种格式×1000次对照全部通过。
- 扩大验证：10种格式×10000次对照全部通过。
- 累计130000次 Graph/普通执行对照，未出现数值不一致；调整前相同程序多次在几百轮内失败。
- 扩大测试期间只读采样记录为核心1980 MHz、显存6809 MHz、GPU59°C（瞬时采样，不代表全程极值）。
- 这强烈支持原频率/电压配置稳定性不足。尚不能据此宣称所有负载均稳定，也不需要把已有现象解释为显卡物理损坏。

## 调整前确认的结果

- 完整模型的旧二进制和当前二进制均曾报告 CUDA illegal memory access，不能归因于本轮 CPU 分片或 Windows DMA 修复。
- 最近一次失败：T=6、position=12、layer29 的常驻显存专家计算（下一层30未到达）。GPU 调度表与 CPU 调度表逐字一致，22组、53条目、PCIe任务0；专家条目和索引在范围内。
- 独立 CUDA 专家程序只运行量化专家内核，无模型服务、CPU专家线程池、磁盘取权重。Graph 与普通执行使用相同输入和同一组内核。
- 普通执行连续两次出现不一致：16/42格式，第174/273轮，各1个浮点数。第一次row3/column1508，第二次row34/column791。值分别为约-1.49811058e-6与-1.49339212e-6，错误方向互换。此前另一次18/42格式第113轮也不一致。
- Compute Sanitizer memcheck：10种格式各200次 Graph/普通执行对照完成，报告0个错误。插桩会改变时序，不能据此排除所有问题。
- 16 GiB显存、64轮零/全1/交替位/地址哈希写入与回读全部通过。它不等同于GPU核心稳定性证明。
- 用户确认有一直启用的降压超频设置。之后的参数调整与测试见文首。

## 后续隔离检查

以下隔离检查发生在用户报告调整参数之前，当时标记为频率状态未确认：

- 使用90f67ea提交中未修改的GPU源文件独立构建，1000轮测试两次均失败。16/42，第450/253轮，分别row31/col1885和row2/col9，均1个浮点数不一致。这排除了新增诊断代码作为独立测试错误的来源。
- 单个原始Q2_0矩阵内核，固定权重和激活，不使用Graph，不经过gate/up或中间量化，连续10000次调用全部逐位一致。故障尚不能定位为某一指令，也不能仅凭分组测试失败断定硬件损坏。



## 后续模型验证

参数调整后的普通模型验证与优化已完成，采用参数、长上下文结果及 CPU 独立异常的限制，统一见 CONTINUOUS-OPTIMIZATION-X16.md。轻量诊断默认关闭，GPU 专家计算内核保持原样。用户自行调整 GPU 参数，代理未修改频率、电压或 BIOS。

早期完整诊断模式曾连续完成 336 个请求，简化诊断后仍复现故障，因此没有把“增加诊断后不崩溃”当作修复证据。

原始稳定性证据：gpu-stability-x16-evidence.zip；历史测试二进制哈希：gpu-stability-binary-hashes.json。最终配置与模型对照证据以 x16-optimization-evidence.zip 为准。
