# Prefill 与缓存优化实测

日期：2026-10-03。单请求并发，原模型、量化、专家 top-k、32768 上下文和上一轮 decode/PLE 优化均保留。

## 已采用的设置

`--prompt-cache-root 512`：共享系统提示/工具定义达到 512 token 就保存根检查点（原门槛 2048）。

`--short-read 448`：每段不超过 448 个新文本 token 时走已有的 verifier 窗口路径（原阈值 64），较大段仍走批量 prefill。没有改变数学内核或提示内容。检查点数量上限仍为 6；短前缀现在会更早占用一份检查点。

新增 `strata_tune.short_read`（整数 0–32768）供同进程比较；未传时每次恢复 CLI 默认值。

## 共享前缀较短时的多次请求

同一新二进制、旧/新配置按 ABBA 顺序各测两次。每组包含 1 次首次读取、4 次不同工具结果的分支请求、1 次完全相同提示的重试。共享前缀为 1004 token。原配置的分支请求缓存命中为 0，新配置为 1004。以下为客户端收到首个非空流式内容的平均时间。

| 场景 | 原配置 | 新配置 | 等待减少 |
|---|---:|---:|---:|
| 分支新增 122 token | 10.69 s | 1.61 s | 85.0% |
| 分支新增 237 token | 11.99 s | 3.55 s | 70.4% |
| 分支新增 397 token | 11.45 s | 5.79 s | 49.4% |
| 分支新增 717 token | 11.77 s | 8.40 s | 28.6% |

6 次请求总耗时（包括生成输出）：平均 **59.64 → 33.03 秒，减少 44.6%**。两次新配置分别为 33.25/32.82 秒。

首次不命中会话缓存的首字时间 **12.66 → 12.73 秒**，没有改善。完全相同提示重试约 90 ms，原配置本来就有这一能力。没有清空 Windows 文件缓存，首次请求不等于冷磁盘测试。

## 固定命中量，隔离短段 prefill 路径收益

同一进程、关闭诊断日志、4 轮平衡顺序。每个对照前插入相同根前缀的短请求，使两组均恢复到 4008 token，避免第二组直接复用第一组完整结果。

| 新读 token | 原阈值 64 | 新阈值 448 | 首字等待减少 |
|---|---:|---:|---:|
| 122 | 3.89 s | 1.65 s | 57.5% |
| 237 | 5.88 s | 3.17 s | 46.0% |
| 397 | 6.57 s | 5.40 s | 17.9% |

长上下文对照：复用 26668 token，两轮平衡测试：

| 新读 token | 原阈值 64 | 新阈值 448 | 首字等待减少 |
|---|---:|---:|---:|
| 122 | 4.25 s | 1.70 s | 60.1% |
| 237 | 5.33 s | 3.11 s | 41.7% |

## 交叉点与波动

筛选时强制逐窗口处理：约 397 个新 token 仍更快，517 token 的均值收益仅约 3%，589–717 token 反而变慢，因此采用 448，而不是无限扩大阈值。筛选带诊断日志，仅用于选值。

717-token 请求在两个阈值下都执行相同批量路径。正式对照加补测每组 8 次，平均首字时间 7.91/8.41 秒，中位数 7.76/7.84 秒；全部慢样本保留。未宣称这一段有收益。

额外做了完全相同参数的假分组对照（两组实际都发送 short_read=64，每组 4 次），平均首字时间 8.37/8.16 秒。原始数据和有效参数保存在 sham.json。这些有限重复不保证每次请求延迟。

- 缓存回归 25 项通过：不同工具结果/码字、分支返回、相同提示重试、连续对话、输出截断、真实生成的工具调用、超过 6 个检查点的多轮保留、改变系统提示后缓存失效。
- 最终正常服务回归 4 项通过：1004-token 根前缀复用、31243-token 完整提示回忆和重复命中。独立重启后，约 1K 首次输入的 prompt 时间 16.59 秒、31K 首次输入 63.58 秒，31K 重复请求恢复 31236 token。这些首次时间仅是回归记录，不是前后性能比较，也说明首次工作集状态会影响延迟。

## 当前瓶颈与边界

这一轮消除了两类额外等待：短共享前缀未被保存导致整段重读，以及小追加段进入批量 prefill 后的专家加载/显存槽位管理等固定开销。较短追加段改走已有的 CPU/GPU 混合窗口路径，能够避开部分开销。

首次长输入和大段新增文本仍要执行完整 prefill；本轮没有新的长输入吞吐提升结论。当前单序列的位置 KV 只容纳一条历史路径，检查点只能恢复位置内容仍有效的前缀；不同系统提示、改写早期历史或切换到无共同前缀的对话仍可能重算。

正确性验证覆盖本次请求和缓存行为，不是全模型质量等价证明。历史偶发 CPU 执行访问异常仍未解释，本轮未因此作硬件故障或已修复的结论。
