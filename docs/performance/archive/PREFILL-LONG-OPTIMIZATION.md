# 长输入 Prefill 优化

2026-10-03。已应用到日常配置，普通服务在 8080 运行。单请求并发，原模型权重、量化、专家 top-k、32768 上下文及此前的 decode/短前缀缓存优化保留。

## 已采用

- `--refill-mode 3`：预填充临时借用的专家显存槽位，改用缓存文件读取、4 个工作线程及每线程两个 pinned 缓冲补回。Windows 读取使用独立的 overlapped 文件句柄，每次读取等待自己的完成事件；缓冲在 DMA 完成前不会复用，所有上传完成后才发布专家驻留表。缓冲有固定上限，约十几 MiB，没有额外复制一份完整专家库。
- `--prefill-ring 192`：流式专家预读的 GPU 槽位由本机自动选择的 96 增至 192，提前准备更多权重，减少 GPU 等待。16K 分块借用的专家槽位由 4334 增至 4465，约多 213 MiB；预填充结束后恢复，原 8974 个显存专家的总容量不变。
- 分块仍为 `--prefill 16384`，保留中途检查点。上下文上限仍为 32768。新功能的源码默认值维持原行为，由本机配置明确启用。

## 正式性能对照

使用本轮开始时保存的旧可执行文件 A，与最终候选 B，按 A1–B1–B2–A2 顺序分别启动进程。每个进程按 31K、8K、16K 的顺序处理，再重复一遍，共 24 个测量请求；每次先发送一个短清理请求，逐次断言前缀缓存命中 `cache_n=0`，检查目标词召回。请求全部串行，测速时无编译或其他基准；关闭 Prefill/Decode timing、TRACE 和字节校验诊断。

下表是引擎输入处理时间的中位数，不含模型启动时间。8K/16K 每组 4 个样本；31K 首次和重复分别每组 2 个样本。Windows 文件缓存没有清空，因此“首次”指进程启动后的第一次长输入，不能称为冷 SSD 测试。样本量有限，首次请求的实际耗时仍有波动。

| 输入 | 原版本 | 优化后 | 耗时减少 |
|---|---:|---:|---:|
| 8,390 token | 14.87 s | 13.86 s | 6.8% |
| 15,956 token | 21.94 s | 17.69 s | 19.4% |
| 31,243 token，进程启动后首次输入 | 70.26 s | 43.92 s | 37.5% |
| 31,243 token，重复完整输入 | 42.28 s | 36.08 s | 14.7% |

客户端另有真实流式首字延迟（不把空 role chunk 当首字），完整样本和中位数见 `prefill-long-summary.json`。所有正式请求的目标词召回通过。这里的收益不代表 decode token/s 提高。

## 瓶颈和实验取舍

原配置的 31K 诊断：热态批量处理约 37.7 s，其中 GPU 时间线中的权重等待约 12.9 s；一次首次补回 7 GiB 权重耗时约 15.1 s。直接把可分页文件映射交给 CUDA，首次触页及驱动 staging 带来长尾。检查点本身每次约 24 ms，并非主要瓶颈。

新组合的 31K 诊断：批量处理约 34.5 s，GPU 时间线中的权重等待约 9.6 s，热态专家补回约 0.64 s。诊断数据只用于定位，不混入正式性能表。主机 staging 与 GPU 工作重叠，不能将两者耗时相加；GPU 事件区间也可能包含等待主机的空闲。

剩余主要开销仍包括 SSD/内存到 GPU 的权重供应等待，以及 GPU 的 HC read、注意力和矩阵运算。这里的 wait-copy 不能单独证明 PCIe 已达到带宽上限。32GB RAM 无法让所有非显存专家都留在 pinned 内存：当前约 10 GiB pinned、15.4 GiB 冷专家，Prefill 又需临时借用部分 GPU 专家空间。

本轮还测过：

- 直接非缓存读取补回：热态更慢，未采用。
- 并行文件映射补回：小工作集有收益，但 32K 分块的大工作集出现明显长尾，未采用。
- 主体异步直读：没有确认稳定的主体等待收益，实验代码已从最终版本移除，日志与实验源文件仍存档。
- 32K 分块：减少重复权重流入，主计算变快，但约需补回 13 GiB，耗时约 5–6 s，而且减少 16K 位置的中途缓存检查点。最终的 16K 分块加 192 槽在本机有更好的整体取舍。

## 正确性与运行状态

- 45 项 GPU staged-refill 测试通过：不同工作线程数、读取方式、尺寸、顺序、稀疏槽位、边界、未覆盖区域及异常清理。
- Windows tiered-source 测试通过，包括 512 次并发缓存/流式读取，覆盖各层级、未对齐区间与文件尾部，逐字节比较。
- 42 项 API/真实 tokenizer 测试通过；CLI 边界与非法输入检查通过。
- 真实 31K 模型请求中，全部 4465 个补回槽位与原始权重逐字节一致；该校验不计入性能结果。
- 25 个缓存/分支/续接/工具结果/截断回归请求通过；断开流式生成后服务回到空闲，下一请求正确。
- 正常配置下，短共享前缀、31K 召回和完整重试缓存通过；最终上下文 32768、服务并发 1、无在途请求。性能诊断与额外字节校验已关闭。
