# GPU / CPU 联合剖析与候选验证

2026-10-02。本机原有 IQ3_XXS 模型；权重、量化、专家 top-k、32K 上下文上限均未改变。

## 结果

完成 CPU 分类型、分主机来源、分每专家 token 数的统计，并修正 GPU 报告混入 prefill 验证窗口的问题。
定位到 CPU 单 token gate/up、文件映射数据的首次访问，以及 GPU 显存专家计算。
另实现并测试跳过零 PCIe 专家请求中的空 GPU 路径；空 PCIe 路径候选保留为显式启用的实验，默认保持原执行图。

## 新的瓶颈证据

联合剖析跑原六题两轮，共 12 请求、372 个解码窗口。逐请求 GPU 计时窗口数与 decode 窗口数一致；
CPU gate/up 和 down 统计的行数分别等于专家组数乘 640 / 2560，24 项覆盖核对通过。

- **约 76% 的 CPU 专家组只有一个 token。** 验证窗口含多个 token，不代表同一个专家能复用多个 token。
- **热态 gate/up 中，IQ3_S 占约 35.4%。** 其次 IQ2_S 19.2%、IQ2_XS 17.8%、IQ2_XXS 14.5%、IQ3_XXS 13.1%。
  这里的 Q3 模型包本来就是混合格式，发现 IQ2 格式不代表这次降低了量化档位。
- **文件映射来源的 gate/up 累计 worker 时间：首轮 54.34 秒，后轮 10.23 秒。** pinned 来源分别 15.05 / 14.93 秒。
  这是并行 worker 的耗时之和，不是整机墙钟时间；文件映射页可能命中 OS 缓存，不能把全部差值精确叫作硬缺页时间。
- **热态行阶段的 host tail 约占 22.5%。** 这是主线程完成自己的任务后等其余任务完成的时间；
  进入和退出停驻状态的等待合计只有约 2.2 ms/整轮六题。下一步应看任务分片尾部，而非盲目改屏障。
- GPU 热态计时：显存专家约 **9.22 ms/窗口**，hc-read1+router 约 **5.19 ms/窗口**，输出头约 **1.76 ms/窗口**。
  GPU 等 CPU 的约 6.78 ms/窗口与 CPU 工作存在重叠，不应再次加到 CPU 时间上。详细计时会扰动执行，因此只用来定位热点。

## 单 token 内核试验

对五类 gate/up 各取一层、八个真实专家，以合成激活比较 ggml 的单 token 路径和现有自有 AVX2 内核。
固定在一个 P 核、一个 E 核；32 行/640 行两种分片，七组交替顺序、每组 64 次调用。

不同格式和核心的结果不一致：IQ2_XXS 自有路径快约 8–12%；IQ2_XS 在 P 核快约 17%，在 E 核更慢；
IQ3_S 在 E 核快约 18–21%，在 P 核略慢；IQ2_S 自有路径在两类核上均明显更慢。
输出最大绝对差约 2.24e-8，反映浮点累加顺序；不是逐位相同。该探针没有捕获真实模型激活。
**没有全局替换单 token 分派。** 完整数据见证据包 `iq_nt1_bench.log`。

## 空 PCIe GPU 路径试验

原路径即使分配零个 PCIe 专家，也执行 waitB、复制/重定位和分组专家内核。
候选每层省七个节点，48 层共 **336 个节点/验证窗口**。例如四 token 图从 2493 降为 2157 个节点。
分别缓存“有 PCIe 路径”和“无 PCIe 路径”的图，避免请求间改变分配比例后误用旧图。

最终对照在同一进程进行：原六题与新增六题，每题最多 128 token，temperature 0、reasoning none。
两种图各预热 12 次；正式两轮每种图各 24 请求，交替先后顺序。
完整图使用 pcie_num=1、精简图使用 pcie_num=0；最多 80 个 distinct 专家，floor(nmiss/256) 恒为零。
已提前让零候选路径跳过 dma_capable CUDA 查询，确保该检查不污染对照。日志确认全部 72 请求 PCIe 专家为零，详细剖析关闭。
两种图共享同一组已加载权重与运行环境。这是预热后的配对比较，不是清空 Windows 文件缓存后的冷启动测试。

| 正式测量 | 完整图 | 跳过空路径 |
|---|---:|---:|
| 请求数 | 24 | 24 |
| 生成 token | 2482 | 2486 |
| 总 decode 秒 | 47.3754 | 54.0809 |
| 汇总 token/s | 52.390 | 45.968 |
| 第一轮 token/s | 53.048 | 50.164 |
| 第二轮 token/s | 51.748 | 42.410 |

汇总变化 **-12.26%**；按每题每轮配对速度比的几何平均变化 **-8.40%**。
含预热的生成文本逐对一致：**29/36 对**。
正式对照仍出现少数 CPU 阶段长停顿和部分生成文本差异。未独立隔离系统内存状态，也未完成这些文本差异的归因；
不能声称跳过空路径必然造成上述全部降速，更不能把候选认定为已经证明输出完全等价。这是保留默认原图的原因。
第一次探索测量存在额外 CUDA 查询的混杂，已单独保存，未用作最终收益判断。
这些结果不能与上一轮含首轮冷访问、且新题上限 256 token 的 47.05 token/s 直接比较。

## 下一步最有价值的工作

优先研究文件映射专家的首次访问：记录逐专家硬缺页/读取与预取完成时间，并测试先处理 pinned 专家是否能让异步预取多获得一些时间。
其次对 IQ3_S 单 token 热点按 P/E 核分别看反汇编、访存和算术开销；再用实际 NT 分布测试任务分片，减少尾部等待。
全局切换自有 AVX2 单 token 内核、仅靠减少 GPU 节点数，都没有证据支持明显的整机提升。
本轮不承诺新的最低速度。新主题、长输入后的性能稳定性仍受 32 GB 主机内存与文件缓存状态影响。
