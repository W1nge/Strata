# Prefill 第五轮：瓶颈定位与实测优化

本轮在 RTX 2080 Ti 22GB / i7-13850HX / 32GB 内存上完成三项候选优化及端到端筛选。日常仍为单并发、32K 上下文、FP16 KV；模型及专家权重量化不变。缓存仍在闲置 180 秒后落盘，3600 秒后删除。

## 三项改动

1. **Turing 上的 HC 投影**：2080 Ti 没有原生 BF16 Tensor Core。本实现按行用二的整数次幂缩放，把符合条件的 BF16 输入精确转换为 FP16，再用 FP16 Tensor Core 和 FP32 累加。每个值都检查转换往返一致；权重不满足条件时整次回退，激活中的例外行单独走原 BF16 路径。仅限 sm75、HC 的两种矩阵形状和足够大的批量，复用原有 64MiB scratch。输入转换无损，但累加顺序改变，所以不声称全模型逐位相同。

2. **长窗口 Top-K**：原快速分支用预留容量判断，设置 256K 后，即使实际输入较短也会落入较慢分支。现在用实际活动块数选分支，并把寄存器缓存路径扩展至 256K。阈值、并列规则和升序索引不变，测试与旧版及 CPU 参考完全一致。

3. **稀疏注意力打分复用 key**：每个 key 连续服务 8 个 query，减少重复读取。保持原 FP32 运算与归约顺序，分数逐位一致；仅在至少 16384 活动块（约 64K 输入）、至少 64 query 时开启，短输入沿用原内核。

**最终关闭 HC 候选**，日常配置为 `--turing-bf16-gemm 0 --prefill-topk-wide 1 --prefill-score-tile 8`。保留的两项针对长窗口；32K 沿用原计算路径，本轮不宣称日常 31K 得到加速。HC 的单算子收益没有充分转化为稳定端到端收益，仍保留为默认关闭的实验开关。

## 瓶颈在哪里

以下分项表对应原版与三项候选全开的另一次 128K 诊断运行，容量同为 256K。诊断会增加事件开销，不能和正式性能表混用。GPU 事件间隔也可能包含主机发射间隙；主机 staging 与 GPU 重叠，不能相加当作总时间。

| 阶段 | 原版 | 新版 |
|---|---:|---:|
| 批量 wall | 242.601 s | 189.824 s |
| 等待专家供应 | 105.589 s | 75.723 s |
| HC down | 9.211 s | 4.679 s |
| HC up | 9.487 s | 6.199 s |
| QSA 打分 | 22.748 s | 19.788 s |
| Top-K | 13.761 s | 2.281 s |
| 稀疏 attention | 13.822 s | 13.944 s |
| 专家 gate/up | 12.575 s | 12.411 s |
| 专家 down | 6.886 s | 6.810 s |

三项目标计算阶段合计约减少 22 秒，但诊断总耗时变化还包含专家供应等待的大幅波动，不能全部归功于新代码。正式 ABBA 用来检查端到端收益是否重现。

**当前最大可见区间仍是专家权重供应。** 新版这次诊断中 wait copy 占 GPU 时间线约 40%。它包括 SSD 读取、主机 staging、调度与 H2D 等环节，不能直接解释为 PCIe 传输耗时或带宽饱和。

在 256K/FP16 配置下，启动日志显示专家显存约 8.44GiB、pinned RAM 10GiB、冷专家约 21.5GiB；Prefill 还借用约 7.63GiB 专家显存做工作区，期间显存专家更少。32K 配置的启动专家显存约 14.54GiB，同样需要借用工作区。长窗口的代价既有更多注意力计算，也有 KV 占用挤压专家驻留。

256K 容量的长输入测试中，物理内存接近用满，磁盘持续读取，PCIe 已确认为 3.0×16。现有 NVML PCIe RX 采样值与工作负载不相称，未用它推断链路饱和。CPU 缺少 AVX-512 不是本轮这些 GPU Prefill 开销的解释。

### 下一步优先级

- 软件：拆分冷读、staging 和 H2D 等待，并统计每 chunk 的冷专家字节；检查跨 chunk 复用、工作区借用和预取深度。已有异步发射与大 ring，不能默认增加线程或双缓冲就一定更快。
- 内存：增加 RAM 容量有望让更多冷专家驻留，从源头减少持续磁盘读取，值得优先验证；仍需按总工作集、PLE、KV 和系统余量重新规划 pinned 预算，不能直接保证某个加速百分比。
- 显存/GPU：更大显存可减少 KV 与专家竞争；更新架构还可能改善 BF16 与 attention。但没有在新硬件实测，不报硬件升级收益。
- KV 量化仍待独立选择和验证。本轮未采用 INT8，也未把日常上限改为 256K。

## 验证与日常配置

BF16 13 例（含 FP64 参考、步幅/尾部、beta、NaN、次正规数和回退），Top-K 12 例（含 CPU/旧内核对照、并列值、NaN/Inf 和边界），scorer 7 例（含逐位、FP64、非单调 query 和尾部边界）通过。三个 Compute Sanitizer memcheck 均为 0 错误；CLI 27 例通过。

集成验证通过完整 31K、驻留重试、落盘恢复、续接、分支、Prefill 取消后恢复、过期删除后重新 Prefill。测试用隔离目录和 5秒/30秒过期时间，开启借用专家恢复核验；日常仍是 180秒/3600秒。

日常启动后再次验证短请求、分支、完整 31K 和缓存命中；服务为单并发、32K、FP16，诊断关闭。没有提交或推送。

## 采用决定及续接专项检查

采用保持分数和选择结果一致的长窗口 Top-K 与 scorer key 复用；HC 继续关闭。三项候选同时开启的正式 ABBA 在日常 31K 未显示稳定收益（首轮更慢，重复基本相当），8K 约 3% 的小样本变化不足以抵消不确定性。128K 首次续接曾显著变慢，但同一请求重复后，HC 关闭/开启分别约 49.9/48.0 tok/s，没有复现持续两倍下降；不能据此认定 HC 是唯一根因。关闭 HC 的补充 128K 测试仍约 204.2 秒。最终组合另做关闭诊断的 128K 验证及真实缓存集成检查，不将三项全开时的 256K 成绩当作最终组合收益。
